# MikeLingo

多接口 AI 网页翻译 Chrome 扩展（Manifest V3）：整页对照翻译、划词翻译、快速翻译小窗，
兼容任意 OpenAI 协议接口（DeepSeek / 硅基流动 / 智谱 / Kimi / 通义 / 豆包 / Gemini / OpenAI 等），地址与模型可自定义。

## 功能

- **多接口互斥切换**：可配置多个翻译接口（DeepSeek / 硅基流动 / 智谱 / Kimi / 通义 / 通义 MT / 豆包 / Gemini / OpenAI 等预设，或任意 OpenAI 兼容地址），同一时刻只启用其中一个，弹窗底部即可切换，密钥各自独立保存
- **兼容翻译专用模型**：填 `qwen-mt-*` 时自动切换调用方式（逐条发送 + `translation_options`，不发 system 提示词），无需用户额外配置
- **三种对照方式**：译文置于原文下方（inline）、左右并列（columns）、仅显示译文（replace）
- **划词翻译**：选中文本后弹出按钮或即时出卡片，支持一键复制；输入框内选中、iframe 内选中同样有效
- **中英互译**：选中/输入的内容本来就是目标语言时自动翻到另一边（中文→英文、英文→中文），卡片与小窗都会标出「译为 X」
- **快速翻译小窗**：点扩展图标即可打字/粘贴临时翻译，目标语言可选「自动（中 ⇄ 英）/ 跟随设置 / 指定语言」，多行按行分别翻译，草稿在会话内保留
- **词典详解**：划词碰到词、短语、专有名词时，除了译文再给一份词典式解释——**分词性的释义、双语例句、
  用法辨析、相关词**，专有名词会说明是什么、在哪、为什么有名（`San Jose` 不再只回"圣何塞"）。
  默认只对短内容自动查，长句留「详细解释」按钮，结果缓存本机不重复计费
- **音标与朗读**：划词卡片和快速翻译里，选中单个英文单词会显示音标（美式 / 英式可选）；
  **单词、整句、中日文都能朗读**——单词走有道真人录音，整句走百度语音合成，
  再不行才回落到系统语音，前面的挂了自动用下一个
- **生词本**：卡片里一键「加入生词本」，连同音标、译文、原句和来源网址一起存下；
  右键菜单和 `Alt+Shift+V` 也能直达，支持搜索、筛选、导出 JSON / CSV、导入
- **间隔复习**：生词本内置 SM-2 记忆曲线复习（忘记 / 模糊 / 记得 / 简单四档，按钮上直接预告下次复习时间），
  空格看答案、`1–4` 评分，全程键盘可用
- **只译外文**：中文占比高的段落自动跳过；`pre / code / script` 等不翻译
- **渐进翻译**：仅翻译进入视口的段落，动态加载的内容自动补翻
- **本地缓存**：IndexedDB 缓存译文（按 `模型 + 目标语言 + 原文` 命中），重复内容不重复计费
- **可配置**：API 地址、模型、温度、并发数、分批大小、超时、译文字体与样式、按站点自动翻译

## 安装（加载未打包扩展）

1. Chrome 打开 `chrome://extensions/`
2. 右上角开启「开发者模式」
3. 点「加载已解压的扩展程序」，**选择项目里的 `MikeLingo/` 子目录**（含 `manifest.json` 的那一层），不是项目根目录
4. 首次使用点扩展图标 → 「设置」，在「翻译接口」里填入 API Key（DeepSeek 为 `sk-` 开头），点「发送测试请求」确认连通后保存

`MikeLingo/` 是 Chrome 长期加载的固定目录，之后升级只覆盖这个目录的内容。

manifest 里带了 `key` 字段，**扩展 ID 固定为 `hkoknpdlmemnbllkdijbcdbkkcmpljmf`**——
未打包扩展的 ID 默认按目录绝对路径派生，项目一挪窝 Chrome 就当成新扩展，
而 `chrome.storage`（API Key、设置、生词本）按 ID 分桶，ID 一变数据就全"消失"。
钉死 ID 之后，换目录、换盘符、重装 Chrome 都不会再丢。详见 [keys/README.md](keys/README.md)。

API Key 存在 `chrome.storage.local`（不随账号同步），按接口分别保存，页面上只回显脱敏预览；留空保存表示保持原密钥不变，删除接口会连带清除它的密钥。

## 配置说明

设置页（`chrome://extensions` → 详细信息 → 扩展程序选项）：

- **翻译接口**：最多 10 个，每个接口独立配置地址 / 模型 / 密钥 / 温度 / 超时，并可单独「发送测试请求」；
  勾选哪个就用哪个（互斥），切换立即生效。默认地址 `https://api.deepseek.com`、模型 `deepseek-chat`，
  兼容任何 OpenAI 格式的 `/chat/completions` 接口。
  填 `qwen-mt-turbo` / `qwen-mt-plus` 这类**翻译专用模型**时，扩展会自动改成逐条发送并传 `translation_options`
  （该类模型不看 system 提示词，自定义提示词与温度对它无效，设置页会给出提示）
- **并发数 / 每批段落数 / 每批字符上限**：并发默认 3、每批 10 段或 1800 字符，站点段落多时可调高，报 429 时调低
- **超时与重试**：默认 60s 超时、失败重试 2 次（指数退避）
- **译文样式**：虚线下划线 / 实线 / 引用条 / 高亮底色 / 无
- **译文字体**：默认中文字体栈（PingFang SC、Microsoft YaHei、Noto Sans SC 回退），字号可按原文百分比缩放

- **音标、发音与生词本**：可关闭音标查询；发音口音在美式 / 英式之间切换（同时决定挑哪条真人音频、
  语音合成用哪种嗓音）；语速 0.5–2；**发音音源**可选自动 / 只用有道 / 只用 dictionaryapi / 不联网；
  「系统语音包」一栏实时显示本机装了哪些语音；「试听发音」按当前表单里的设置立即试听，不必先保存

接口报错会把服务端返回的原始 message 一起显示（如 401 `Authentication Fails`、402 余额不足、429 限流），不做笼统的「翻译失败」。

## 词典详解

翻译通道的系统提示词明确禁止模型解释（`Never explain`），否则整页翻译会混进解说文字。
所以详解是**另一条通道**：另一套提示词、单独一次请求、要求返回固定形状的 JSON，再渲染成卡片里的一块。

| 设置（设置页 → 划词翻译 → 词典详解） | 行为 |
| --- | --- |
| **自动**（默认） | 5 个英文单词 / 12 个汉字以内的短内容，翻译的同时自动查详解；长句只给按钮 |
| **手动** | 一律不自动查，卡片底部点「详细解释」才发请求 |
| **关闭** | 只给译文，不显示详解入口 |

### 翻译和详解用两个不同的模型

翻译适合用 `qwen-mt-turbo` 这类**翻译专用模型**（便宜、专精），但它做不了详解——不看提示词，
只会把原文再翻一遍。所以两者可以分开配：

| 场景 | 怎么配 |
| --- | --- |
| **同一家服务商**（同地址同密钥，只是模型不同） | 接口的「模型（翻译用）」填 `qwen-mt-turbo`，设置页「划词翻译 → **详解使用的模型**」填 `qwen-plus`。**不用配第二个接口** |
| **两家不同服务商** | 在「翻译接口」里再加一个接口，然后把「详解使用的接口」指向它 |
| **两者共用一个模型** | 「详解使用的模型」留空、「详解使用的接口」选「跟随翻译接口」即可 |

「详解使用的模型」下方会实时显示**详解实际会用到的接口与模型**；一旦落到翻译专用模型上，
设置页当场红字提示，不用等划词才发现出不来。

- 详解按「模型 + 目标语言 + 原文」缓存在本机 IndexedDB，同一个词再划不重复计费
- 加入生词本时详解一并存下，**复习时答案区直接给释义和例句**，词表里折叠显示，导出 CSV 多一列 `explain`
- 模型没按格式返回时会明确说"没按格式返回，可换个模型"，不会静默空白
- **翻译专用模型（`qwen-mt-*`）不支持详解**——它们不看 system 提示词，只会把原文再翻一遍，
  这种情况下会提示切换到 `deepseek-chat` 这类通用对话模型

## 生词本与复习

- 词条存在本机 IndexedDB（`dst-vocab`），**不上传任何服务器**；换电脑前在生词本页面「导出 JSON」，
  到新机器「导入 JSON」即可，同一个词会按复习进度靠前的那条合并，不会把已经背熟的词打回新词
- 复习排程用 SM-2 简化版（和 Anki 同源）：`ease` 记难度、`interval` 记间隔天数，间隔超过 21 天算「已掌握」；
  答「忘记」的词 10 分钟后在本轮里再出现一次，当天就能补
- 四个评分按钮上直接写着「下次什么时候再问」，用的是和后台完全同一份排程代码（`src/common/schedule.js`），
  不会出现"按钮上写 3 天、实际排到 5 天"
- 导出 CSV 带 UTF-8 BOM，Excel 直接打开不乱码

### 音标和发音数据来自哪里

朗读按下面的顺序依次尝试，前一个失败自动用下一个：

| 顺序 | 服务 | 能读什么 | 需要外网 | 说明 |
| --- | --- | --- | --- | --- |
| 1 | 有道 `dict.youdao.com/dictvoice` | 英文单词、3 词内短语 | 是 | **词典真人录音**，音质最好；整句会返回 500，直接跳到下一条 |
| 2 | 百度 `fanyi.baidu.com/gettts` | 整句、中文、日文、韩文，1000 字以内 | 是 | 语音合成；国内外都能直连 |
| 3 | dictionaryapi.dev 的 media 节点 | 英文单词 | 是 | **音频服务经常返回 502**，只当最后的备选 |
| 4 | 系统语音包（`chrome.tts`） | 任何内容 | **否** | 不联网，但要求电脑装了对应语言的语音包 |

音标另外走 [dictionaryapi.dev](https://dictionaryapi.dev) 的 JSON 接口（免费无密钥，只发单个英文单词，结果缓存本机半年）。

语速统一在播放端用 `playbackRate` 调（开了 `preservesPitch`，不会变声），几个音源的语速表现才一致。
日文假名、韩文谚文会单独识别语种——`guessTextLang` 把假名也算作 CJK，直接拿它挑嗓音会把日文念成中文。

**隐私**：朗读的文字会发给对应服务商（有道 / 百度），整句朗读就是整句发出去。
设置页的「发音音源」可以只选其中一个，或者选「不联网，只用系统语音合成」——选了之后不再发起任何音频请求。
关掉「查询单词音标与真人发音」则连音标查询也不发。

发音音频在 offscreen 文档里播放：宿主站点的 CSP（`media-src`）会拦掉内容脚本里的音频，
而且直接在页面里播会打断站点自己的音视频。

### 发音没声音？

按这个顺序排查（设置页「音标、发音与生词本」里有「系统语音包」状态和「试听发音」，会直接告诉你走的是哪条路）：

1. **点「试听发音」看提示**。成功时会写明用的是「有道真人发音 / 百度语音合成 / dictionaryapi 真人发音 / 系统语音合成」；
   失败时会把在线音源和本地语音两头的原因一起列出来。
2. **换了电脑就没声音，最常见的原因是新电脑没装语音包**。设置页的「系统语音包」一栏会显示检测结果，
   显示"没有检测到任何系统语音包"就说明语音合成这条路是断的。
   Windows：设置 → 时间和语言 → 语音 → 管理语音 → 添加语音（英语 美国）。
3. **外网不通**时（公司网络、无代理），有道和百度通常仍能直连，dictionaryapi.dev 可能超时——
   此时音标不显示是正常的，发音仍应可用。都不通就只能靠语音包。
   选中内容超过 1000 字时不会发起在线请求，提示会点明是长度超限而不是网络问题。
4. 以上都正常还没声音，检查系统音量和输出设备；扩展的音频在后台文档里播，不受网页静音标签影响。

## 升级

有三条路，日常用第一条：

### 1. 设置页一键更新（推荐）

设置页 →「版本与更新」→ **检查更新** → **下载并安装**。
它会从 GitHub Releases 下载发布包、解包、写回安装目录，然后自动重载扩展——
不用跑批处理，也不用去 `chrome://extensions` 点刷新。

首次安装时浏览器会让你**选一次安装目录**（就是 `MikeLingo/`）并点「允许修改文件」，之后就记住了。
这是 Chrome 的 File System Access 授权，扩展本身没有任意写文件的权限。

因为是"从网上下东西覆盖本机文件"，装之前卡了四道校验，任一不过就中止并说明原因：
只认配置的那个 GitHub 仓库和 GitHub 自家域名；包内路径只允许 `manifest.json` / `src/**` / `icons/**`；
包内 manifest 的 `name` 与 `key` 必须与当前扩展一致、版本必须更新；目标目录必须确实是 MikeLingo 的安装目录。

### 2. 批处理（离线、可回滚到任意历史版本）

双击 `Release/v<版本>/一键升级.bat`，它把该版本覆盖回 `..\..\MikeLingo`，
然后到 `chrome://extensions` 点一下 MikeLingo 卡片上的「刷新」。
批处理里的路径全部由 `%~dp0` 推导，**整个项目文件夹换位置、改名都照样能用**；
`src/`、`icons/` 用 `robocopy /MIR` 镜像覆盖，旧版本里删掉的文件不会残留。
装**旧版本**（回滚）只能用这条。

### 3. 手动

从 Releases 下载 zip，解压后覆盖 `MikeLingo/`，再去扩展页刷新。

> 三种方式都只动 `MikeLingo/` 里的程序文件，**不碰 Chrome 的用户数据**：
> API Key、设置、生词本都挂在扩展 ID 下，而 ID 已被 manifest 的 `key` 钉死，升级不会丢。
> 唯一会丢数据的操作是在 `chrome://extensions` 点「移除」——那是卸载，别点。

## 发布一个新版本

```bash
# 1. 改 MikeLingo/manifest.json 里的 version（顺手同步 package.json）
node tools/pack.cjs        # 产出 Release/v<version>/：解压态副本 + zip + 一键升级.bat

# 2. 发到 GitHub Releases
#    tag 必须是 v<version>，附件必须叫 MikeLingo-v<version>.zip——
#    设置页的「检查更新」就是按这两条规则找包的，改了名字就找不到
gh release create v1.10.0 Release/v1.10.0/MikeLingo-v1.10.0.zip --title "v1.10.0" --notes-file notes.md
```

`notes.md` 就是本次的更新说明（可以直接从 CHANGELOG 里对应小节复制），
它会原样显示在设置页的「更新说明」里，写清楚这版改了什么。

发完可以自查一遍：

```bash
gh release view v1.10.0 --json tagName,assets --jq '{tag: .tagName, assets: [.assets[].name]}'
```


改了 `tools/pack.cjs` 里的批处理模板后，`node tools/pack.cjs --bats` 可一次性刷新所有历史版本目录里的 bat。

打包只收 `manifest.json`、`src/`、`icons/`——它们都在 `MikeLingo/` 里，`tools/`、`node_modules/`、
`package*.json`、`README.md`、`Release/` 天然进不了包。

不要用 `Compress-Archive` 打包：Windows PowerShell 写出的 zip 条目名带反斜杠，不符合 ZIP 规范
（4.4.17.1 要求 `/`），Chrome 应用商店解包可能出错。`tools/pack.cjs` 固定用正斜杠，并使用固定时间戳，
源码不变时打出的包字节一致，便于比对。
